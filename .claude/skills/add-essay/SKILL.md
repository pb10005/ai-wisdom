# エッセイを知恵袋に追加する

## 手順

1. **本文を確定する**
   - ユーザーが本文を貼った場合はそれを使う。会話からまとめる場合は、下書きを見せて確認を取ってから保存する。
   - PDF などのファイルで渡された場合は、下の「ファイルから取り込む」に従って Markdown に起こす。
   - 本文の主張は書き換えない。整えるのは見出し・誤字・段落程度に留める。

2. **メタデータを決める**
   - `title`: 本文の主旨が分かる日本語タイトル。
   - `date`: 執筆日（不明なら今日）。`YYYY-MM-DD`。
   - `tags`: 2〜5 個。既存エッセイのタグを `grep -h '^tags:' essays/**/*.md` で確認し、なるべく再利用する。
   - `collaborators`: 共同執筆者（例: `[human, claude]`）。ファイルの署名（`@名前` など）があればそれを使う。
   - `source`: ファイルから取り込んだ場合のみ、原本へのエッセイからの相対パス。
   - `extracted: false`、`wisdom: []` で固定。

3. **ファイルを作る**
   - パス: `essays/<YYYY>/<YYYY-MM-DD>-<slug>.md`
   - `slug` は英小文字とハイフンの短い要約（例: `2026-10-07-small-steps.md`）。同名があれば `-2` を付ける。
   - `essays/_template.md` の構成（きっかけ / 本文 / 結論・気づき）に沿う。元の文章が別構成でも無理に変形しなくてよいが、「結論・気づき」節は可能な限り付ける（ファイルから取り込む場合は付け足さない）。

4. **検証する**: `python3 scripts/check.py`

5. **報告する**: 保存したパスを伝え、続けて知恵を抽出するか（`extract-wisdom`）をユーザーに尋ねる。

## ファイルから取り込む（PDF）

元が Claude Docs や Notion などの文書なら、まず Markdown で書き出してもらうのが最も劣化が少ない。
PDF しかない場合は次の手順で起こす。機械変換の結果をそのまま保存しない。

1. **原本と図を保存する**
   - 原本: `essays/<YYYY>/assets/<エッセイの .md と同じ名前（拡張子なし）>/original.pdf`
   - 埋め込み画像: `pdfimages -list` で確認し、`pdfimages -png` で取り出して同じディレクトリに `fig-1.png`, `fig-2.png`… として置く。
2. **テキストを取り出す**: `pdftotext <pdf> -`。リンク先 URL は `pdfinfo -url <pdf>` で取れる。
3. **ページ画像と突き合わせて整える**: `pdftoppm -r 70 -png <pdf> <prefix>` でページを画像にし、Read で見ながら以下を直す。
   - 段落内の改行をつなぎ、ページヘッダー（文書タイトル）・フッター（`Page n of m`）・日付と署名の行を除く。
   - 見出しは `##`、番号付き・箇条書きリストを復元する。太字などの装飾は原本にあるものだけ付ける。
   - 表は列が崩れて抽出されるので、ページ画像を見て Markdown の表に組み直す。
   - 数式は `$$ ... $$`、上付き文字（2ⁿ など）は原本どおりに書く。
   - 図は `![キャプション](assets/<stem>/fig-N.png)` で埋め込み、直後に `> **図の内容**:` として図の内容を文章で書く（テキストしか読めないエージェントや知恵の抽出のため）。
   - 出典リストはリンク付きで復元する。
4. **本文が欠けていないか照合する**: 空白・記号を除いた PDF テキストと Markdown 本文を `difflib` などで比べ、差分が表の並び順や図のキャプション程度に収まることを確認する。
5. 本文の文体・構成は原本のまま残す。テンプレートの「きっかけ / 本文 / 結論・気づき」に組み替えない。
