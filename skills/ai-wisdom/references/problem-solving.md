# 問題解決

行き詰まった問題の進め方と、問題の「大きさ」の取り違えを防ぐための知恵。

### W-0001 いま到達点を決めている制約を、候補を数値で比べて特定してから手を打つ

- status: active
- tags: [制約, ボトルネック, 見積もり]
- 使う場面: 性能・規模・成果などが頭打ちになっていて、何を改善すべきか決めるとき。改善策を提案する前。
- 指針:
  - 限界の原因になりうる制約を列挙し、それぞれが効き始める値（どこで限界になるか）を概算で並べる。
  - 最も手前で効く一つを「いまのボトルネック」とし、そこに手を打つ。他の制約への対策は後回しにする。
  - 概算に置いた前提（使った値）を明示し、前提を変えても大小関係が変わらないかを確かめる。
- 理由: システムの到達点は、そのとき最も厳しい一つの制約で決まる。どれが本当の次の制約かは、数値で並べて比べないと見誤りやすい。紙の例では「繊維の大きさ（約13km）」より手前の「自重（数百m）」が先に限界になった。
- 例外・注意: 一つの制約を外しても限界はなくならず、二番目に厳しかった制約が次のボトルネックになる。改善のたびにこの手順を繰り返す。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0002 制約が目的にとって本質的か、選んだ手段に付いてくるものかを見分けて、外し方を変える

- status: active
- tags: [制約, 問題の立て方, リフレーミング]
- 使う場面: ボトルネックを特定した後、どう対処するかを決めるとき。改良を重ねても伸びが小さいとき。
- 指針:
  - 「この制約は、手段を変えても残るか」を問う。残らないなら手段に付いてくる制約、残るなら目的にとって本質的な制約とみなす。
  - 手段に付いてくる制約なら、手段そのものを変えて外す。
  - 本質的な制約なら、材料や性能の改良で少しずつ押し広げるより先に、問題の立て方を反転できないか（積む→吊るす、こちら側から→向こう側から）を検討し、選択肢としてユーザーに示す。
- 理由: 改良は制約を少しずつ押し広げる手段にすぎない。紙の例で最も大きく前進したのは、圧縮を引張に、地球側を月側に置き換えて問題の向きを反転させたときだった。折り目の損失は「折る」という手段の制約で、折るのをやめれば消えたが、体積保存はどの手段でも消えなかった。
- 例外・注意: 問題の立て方を変えると、得られる解が元の目的からずれることがある（W-0003）。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0003 制約を外したら、「解いた」のか「別の場所に移した」だけかと、解がまだ元の目的を満たすかを確かめる

- status: active
- tags: [制約, 検証, 目的のずれ]
- 使う場面: ある対策で限界が消えたように見えるとき。制約を外す工夫を何段階か重ねた後。
- 指針:
  - 消えたはずの量（コスト・負荷・増え方）が、別の場所に移っていないかを確認する（例: 高さの上限は消えたが、指数関数的な増加が底面積に移っただけ）。
  - 制約を外すたびに、得られた解がユーザーの元の目的をまだ満たしているかを照合する。ずれていれば、その旨をはっきり伝える。
- 理由: 先細りの柱は高さの上限を消したが、2ⁿ で増える量を底面積に移しただけだった。また、出発点の「紙の厚さで月に届く」は、制約を外すうちに「地球の近くと月をケーブルでつなぐ」へと目的そのものが変わっていた。
- 例外・注意: 目的が変わること自体は悪くない。黙って変えずに、変わったことを明示して合意を取る。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0011 問題が起きている規模・抽象度と、見方や打ち手の規模・抽象度を合わせる

- status: active
- tags: [ミクロとマクロ, 合成の誤謬, 生態学的誤謬, 問題解決]
- 使う場面: 原因分析や対策を提案するとき。議論がかみ合わないとき。
- 指針:
  - 「いま話しているのは一人（一部署）の話か、全体の話か」「一般論か、この事例に固有の事情か」を最初に確認する。
  - 仕組みが生んでいる問題を個人のミスや心がけで片づけない（仕組みが残れば再発する）。逆に、局所的な問題に大がかりな制度改革をぶつけない。
  - 一般的に効く手法やベストプラクティスを勧めるときは、その手法が前提にしている条件がこの事例で成り立つかを確かめてから勧める。一つの成功例から一般化するときは、成功を支えた人や状況を確認する。
  - 「コミュニケーション不足」のような抽象語でまとめて終わらせず、誰が何を変えるのかまで具体化する。
- 理由: 一人で正しいことが全員でも正しいとは限らず（合成の誤謬）、全体の傾向が一人に当てはまるとも限らない（生態学的誤謬）。問題解決の典型的な失敗の多くは、問題の規模・抽象度と打ち手のそれとの食い違いから生じる。
- 例外・注意: 反対側への行き過ぎにも注意する。何でも「構造が悪い」で止めて個人やチームがいまできる工夫を検討しないこと、「うちは特殊だから」と一般的な知見を拒むことも同じ種類の誤りである。
- 出典: [ミクロとマクロをつなぐリテラシー](../../../essays/2026/2026-10-07-micro-macro-literacy.md)

### W-0013 個人の視点で出した結論は全体の視点で、全体の視点で出した結論は個人の視点で検証し直す

- status: active
- tags: [ミクロとマクロ, 検証, 非線形]
- 使う場面: 対策・方針・推奨を確定させる前の見直し。
- 指針:
  - 一人にとって合理的な行動を勧めるときは「全員が同じことをしたらどうなるか」を考える（例: 全員が節約すると全員の収入が減る、全員が立つと誰も見えない）。
  - 全体の傾向や統計に基づく施策を勧めるときは「目の前のこの人にとってはどうか」を考え、集団の傾向で個人にラベルを貼らない。
  - 「少し増やせば少し良くなる」と線形に延長せず、ある一線を越えると性質が急に変わる境目がないかを考える。
  - まとめる過程で捨てた細部が、個人の判断には決定的でないかを確認する。
- 理由: 片方の視点だけで出した結論は、もう片方の視点で見ると誤っていることが多い。この往復は、規模や抽象度の取り違えによる偏りのどれにも効く。
- 例外・注意: 要素同士が互いに影響し合わない（時計の部品のような）対象では、部分の理解がそのまま全体の理解になりやすく、往復の重要度は下がる。
- 出典: [ミクロとマクロをつなぐリテラシー](../../../essays/2026/2026-10-07-micro-macro-literacy.md)

### W-0017 問題が起きたら、対策を考える前に「何が・いつから・どこで・どの程度起きているか」を事実として把握する

- status: active
- tags: [問題解決, 問題の把握, 事実と解釈]
- 使う場面: 障害・不具合・成果の悪化などを報告されたとき。ユーザーから「どうすればいい？」と聞かれ、すぐに解決策を出したくなったとき。
- 指針:
  - 解決策を挙げる前に、何が・いつから・どこで・どの程度起きているかを確かめる（「売上が落ちた」ではなく「先月から新規顧客の売上だけが前年比で3割減り、既存顧客は横ばい」まで言える状態にする）。
  - 最初の報告に含まれる解釈（「お客さんが離れている」）と事実（「来店数が減った」）を分け、解釈をそのまま問題として受け取らない。
  - どこで起きていて、どこでは起きていないのかを確かめる。この違いが原因を特定する最大の手がかりになる。
  - 分からない点はユーザーに尋ねるか、調べる。答えに詰まる箇所が、そのまま調べるべき箇所になる。
- 理由: 把握が甘いまま進むと、そもそも解くべき問題を取り違える。把握と原因特定を経ずに打った対策は、当たれば幸運、外れれば問題を複雑にするだけの賭けにすぎない。
- 例外・注意: 被害が広がっている最中なら、把握より先に応急処置を行ってよい（W-0019）。
- 出典: [対処の前に、二つの段階がある](../../../essays/2026/2026-10-07-two-stages-before-action.md)

### W-0018 把握した事実は症状として扱い、原因は仮説を立てて検証で絞り込む

- status: active
- tags: [問題解決, 原因分析, 仮説検証]
- 使う場面: 不具合や問題の原因を推定するとき。もっともらしい原因が一つ見つかったとき。
- 指針:
  - 症状と原因を分ける。症状を消す対策（解熱剤）と原因を取り除く対策を混同しない。
  - 原因の仮説を複数立て、データや現場で確かめ、外れたものを消していく。
  - 最初に思いついた原因に飛びつかない。「他の原因では説明できないか」「この原因が正しいなら、他にも起きているはずのことが本当に起きているか」を確かめてから、原因を確からしいと言う。
  - 似た問題を解決した経験は仮説を立てるのに使うが、検証の代わりにしない。
- 理由: もっともらしい説明が一つ見つかると、人はそこで考えるのをやめてしまう。見た目が似ていても原因が同じとは限らない。原因が集客経路にあるのに接客研修を強化しても売上は戻らないように、原因に合わない対策は時間とお金を回収できない。
- 例外・注意: 検証は無制限に続けるものではない。焦りや急かしがある場面では、調べる時間を区切る（W-0020）。
- 出典: [対処の前に、二つの段階がある](../../../essays/2026/2026-10-07-two-stages-before-action.md)

### W-0019 被害の拡大を止める応急処置は先に打ってよいが、それで問題が終わったと扱わない

- status: active
- tags: [問題解決, 応急処置, 根本対策, 障害対応]
- 使う場面: 障害・事故・インシデントの対応。症状が収まったように見えたとき。
- 指針:
  - 被害が広がっているなら、原因究明より先に、または並行して、被害を止める応急処置を行う（システム障害ならまず切り戻して復旧させる）。
  - 応急処置と根本対策を区別して伝える。応急処置の後に「これで解決しました」と報告せず、把握と原因特定が残っていることを明示する。
  - 応急処置で止めたら、何が起きたのか（把握）、なぜ起きたのか（原因特定）を確かめ、原因に合った根本対策を打つ。
- 理由: 表面的な対処でいったん収まると、人は解決したと思い込む。原因が手つかずのまま残れば、同じ問題がときにより大きな形で戻ってくる。原因を理解しないまま仕組みに手を入れると副作用が出て、元の問題と絡み合い、原因を探すのがさらに難しくなる。
- 例外・注意: これは何もせずに調べ続けることを勧めるものではない（火事なら原因究明より先に火を消す）。なお、応急処置で何を変えたかを記録しておくと後の原因特定に役立つ（エッセイ外の補足）。
- 出典: [対処の前に、二つの段階がある](../../../essays/2026/2026-10-07-two-stages-before-action.md)

### W-0021 不合理が残っている・あるべきものが生まれないときは、「何がそれを守っている（阻んでいる）のか」と問いを反転させる

- status: active
- tags: [組織, 不合理, 阻害要因, 根本原因]
- 使う場面: 誰もが無駄だと言う慣習・手続き・仕組みについて相談されたとき。明らかに必要な改善（自動化・ノウハウ共有・連携など）が実現しない理由を考えるとき。廃止や導入を提案する前。
- 指針:
  - 「なぜこんな無駄があるのか」「なぜ誰もやらないのか」ではなく、「何がこの無駄を守っているのか」「何が生まれるのを阻んでいるのか」を問う。
  - 次の問いで阻害要因を探す（欠けているものについては「やめる」を「始める」に読み替える）: やめたいと一番強く思っている人は、やめる権限を持っているか／やめた結果何かが起きたら誰が責められるか／自分たちの外側の何と繋がっているか／始まった理由を今誰か知っているか／消えたら困る人はいないか。
  - 阻害要因の型を当てはめる: 捨てる人と得をする人が違う／失敗の非対称性（続けた損は誰のせいにもならず、やめて起きた事故はやめた人のせいになる）／外部の制約との結合／障害物が見えない／切り替えの一時的な山／無駄が別の役割を担っている。
  - 個別の無駄をなくす・個別の改善を押し付けるより、阻害要因を取り除く案を優先して示す。別々の不満が同じ阻害要因に行き着くことも多い。
- 理由: 集団には、無駄を削ぎ落とし負荷を下げる工夫を根付かせる力が働いている。それでも残る・生まれないなら、流れを塞ぐ何かがある。無駄そのものを見る問いは「意識が低い」「古い体質」といった人や文化への非難で終わりやすいが、阻害要因を見る問いは労力・リスク・権限・情報の流れに目を向けさせる。阻害要因がなくなれば、無駄は自然に削られ、必要なものは根付く。
- 例外・注意: 集団の流れがたどり着くのは局所最適であって、最善である保証はない。表記や形式が誘導しているケースは W-0015 も参照する。
- 出典: [不合理はなぜ残り、合理はなぜ根付かないのか](../../../essays/2026/2026-10-07-what-protects-irrationality.md)
