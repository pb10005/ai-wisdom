# 問題解決

行き詰まった問題の進め方と、問題の「大きさ」の取り違えを防ぐための知恵。

### W-0001 いま到達点を決めている制約を、候補を数値で比べて特定してから手を打つ

- status: active
- tags: [制約, ボトルネック, 見積もり]
- 使う場面: 性能・規模・成果などが頭打ちになっていて、何を改善すべきか決めるとき。改善策を提案する前。
- 指針:
  - 限界の原因になりうる制約を列挙し、それぞれが効き始める値（どこで限界になるか）を概算で並べる。
  - 最も手前で効く一つを「いまのボトルネック」とし、そこに手を打つ。他の制約への対策は後回しにする。
  - 概算に置いた前提（使った値）を明示し、前提を変えても大小関係が変わらないかを確かめる。
- 理由: システムの到達点は、そのとき最も厳しい一つの制約で決まる。どれが本当の次の制約かは、数値で並べて比べないと見誤りやすい。紙の例では「繊維の大きさ（約13km）」より手前の「自重（数百m）」が先に限界になった。
- 例外・注意: 一つの制約を外しても限界はなくならず、二番目に厳しかった制約が次のボトルネックになる。改善のたびにこの手順を繰り返す。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0002 制約が目的にとって本質的か、選んだ手段に付いてくるものかを見分けて、外し方を変える

- status: active
- tags: [制約, 問題の立て方, リフレーミング]
- 使う場面: ボトルネックを特定した後、どう対処するかを決めるとき。改良を重ねても伸びが小さいとき。
- 指針:
  - 「この制約は、手段を変えても残るか」を問う。残らないなら手段に付いてくる制約、残るなら目的にとって本質的な制約とみなす。
  - 手段に付いてくる制約なら、手段そのものを変えて外す。
  - 本質的な制約なら、材料や性能の改良で少しずつ押し広げるより先に、問題の立て方を反転できないか（積む→吊るす、こちら側から→向こう側から）を検討し、選択肢としてユーザーに示す。
- 理由: 改良は制約を少しずつ押し広げる手段にすぎない。紙の例で最も大きく前進したのは、圧縮を引張に、地球側を月側に置き換えて問題の向きを反転させたときだった。折り目の損失は「折る」という手段の制約で、折るのをやめれば消えたが、体積保存はどの手段でも消えなかった。
- 例外・注意: 問題の立て方を変えると、得られる解が元の目的からずれることがある（W-0003）。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0003 制約を外したら、「解いた」のか「別の場所に移した」だけかと、解がまだ元の目的を満たすかを確かめる

- status: active
- tags: [制約, 検証, 目的のずれ]
- 使う場面: ある対策で限界が消えたように見えるとき。制約を外す工夫を何段階か重ねた後。
- 指針:
  - 消えたはずの量（コスト・負荷・増え方）が、別の場所に移っていないかを確認する（例: 高さの上限は消えたが、指数関数的な増加が底面積に移っただけ）。
  - 制約を外すたびに、得られた解がユーザーの元の目的をまだ満たしているかを照合する。ずれていれば、その旨をはっきり伝える。
- 理由: 先細りの柱は高さの上限を消したが、2ⁿ で増える量を底面積に移しただけだった。また、出発点の「紙の厚さで月に届く」は、制約を外すうちに「地球の近くと月をケーブルでつなぐ」へと目的そのものが変わっていた。
- 例外・注意: 目的が変わること自体は悪くない。黙って変えずに、変わったことを明示して合意を取る。
- 出典: [「紙を42回折ると月に届く」の制約を外していくと、宇宙エレベーターに行き着く](../../../essays/2026/2026-10-07-paper-folding-to-moon.md)

### W-0011 問題が起きている規模・抽象度と、見方や打ち手の規模・抽象度を合わせる

- status: active
- tags: [ミクロとマクロ, 合成の誤謬, 生態学的誤謬, 問題解決]
- 使う場面: 原因分析や対策を提案するとき。議論がかみ合わないとき。
- 指針:
  - 「いま話しているのは一人（一部署）の話か、全体の話か」「一般論か、この事例に固有の事情か」を最初に確認する。
  - 仕組みが生んでいる問題を個人のミスや心がけで片づけない（仕組みが残れば再発する）。逆に、局所的な問題に大がかりな制度改革をぶつけない。
  - 一般的に効く手法やベストプラクティスを勧めるときは、その手法が前提にしている条件がこの事例で成り立つかを確かめてから勧める。一つの成功例から一般化するときは、成功を支えた人や状況を確認する。
  - 「コミュニケーション不足」のような抽象語でまとめて終わらせず、誰が何を変えるのかまで具体化する。
- 理由: 一人で正しいことが全員でも正しいとは限らず（合成の誤謬）、全体の傾向が一人に当てはまるとも限らない（生態学的誤謬）。問題解決の典型的な失敗の多くは、問題の規模・抽象度と打ち手のそれとの食い違いから生じる。
- 例外・注意: 反対側への行き過ぎにも注意する。何でも「構造が悪い」で止めて個人やチームがいまできる工夫を検討しないこと、「うちは特殊だから」と一般的な知見を拒むことも同じ種類の誤りである。
- 出典: [ミクロとマクロをつなぐリテラシー](../../../essays/2026/2026-10-07-micro-macro-literacy.md)

### W-0013 個人の視点で出した結論は全体の視点で、全体の視点で出した結論は個人の視点で検証し直す

- status: active
- tags: [ミクロとマクロ, 検証, 非線形]
- 使う場面: 対策・方針・推奨を確定させる前の見直し。
- 指針:
  - 一人にとって合理的な行動を勧めるときは「全員が同じことをしたらどうなるか」を考える（例: 全員が節約すると全員の収入が減る、全員が立つと誰も見えない）。
  - 全体の傾向や統計に基づく施策を勧めるときは「目の前のこの人にとってはどうか」を考え、集団の傾向で個人にラベルを貼らない。
  - 「少し増やせば少し良くなる」と線形に延長せず、ある一線を越えると性質が急に変わる境目がないかを考える。
  - まとめる過程で捨てた細部が、個人の判断には決定的でないかを確認する。
- 理由: 片方の視点だけで出した結論は、もう片方の視点で見ると誤っていることが多い。この往復は、規模や抽象度の取り違えによる偏りのどれにも効く。
- 例外・注意: 要素同士が互いに影響し合わない（時計の部品のような）対象では、部分の理解がそのまま全体の理解になりやすく、往復の重要度は下がる。
- 出典: [ミクロとマクロをつなぐリテラシー](../../../essays/2026/2026-10-07-micro-macro-literacy.md)
